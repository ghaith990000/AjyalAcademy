# Decision log

ADR-style. Newest at the bottom. Add an entry whenever you make a non-obvious choice or change a rule. Status: **Accepted** unless noted.

## Confirmed by the product owner

| ID    | Decision                                                                                                                                                               |
| ----- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D-001 | **Backend = Supabase** (Postgres + Auth + RLS + Realtime + an Edge Function). Chosen over Firebase/custom API for SQL reports, RLS roles and speed.                    |
| D-002 | **Pricing model:** one shared subscription per group, billed monthly; covers 1–4 players; plan chosen by player count (Solo 20 / Duo 35 / Trio 50 / Quad 60 BD).       |
| D-003 | **Discounts:** admin-defined reusable codes (percent or fixed BD, optional expiry/max uses) **and** a manual one-off discount per subscription with a required reason. |

## Assumptions made by Claude (change freely — tell Claude)

| ID    | Decision                                                                                                                                                                                                                                                                                                                                               | Why / impact                                                                                                                                                                                                                                                  |
| ----- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D-010 | **Money stored as integer fils** (1 BD = 1000 fils).                                                                                                                                                                                                                                                                                                   | BHD has 3 decimals; avoids float errors in sums and reports.                                                                                                                                                                                                  |
| D-011 | **One coach per player** (`players.coach_id`).                                                                                                                                                                                                                                                                                                         | Matches "distribution of players to coaches". Many-to-many would complicate rosters/permissions.                                                                                                                                                              |
| D-012 | **T-shirt and transport fees are per player** inside a subscription; T-shirt only for a player's first-ever subscription (editable by admin).                                                                                                                                                                                                          | The request says "for first time joining" and "if the player wants transportation".                                                                                                                                                                           |
| D-013 | **Discount applies to the full subtotal** (plan + T-shirt + transport), capped at the subtotal.                                                                                                                                                                                                                                                        | Simplest reading; one function to change if the owner wants plan-only.                                                                                                                                                                                        |
| D-014 | **"Collected" = payments** (by `paid_at`), not subscription totals. Subscriptions default to "paid in full" on creation; partial/later payments supported.                                                                                                                                                                                             | The request says "fees collected". Enables balances and unpaid tracking.                                                                                                                                                                                      |
| D-015 | **Soft delete** for players and subscriptions.                                                                                                                                                                                                                                                                                                         | Preserve financial/attendance history; log who removed.                                                                                                                                                                                                       |
| D-016 | **Coach permissions:** add/edit/remove own players; create subscriptions & payments for own players; schedule own sessions and take attendance; see own activity only. Admin-only: coaches, assignment, plans/settings, discounts, expenses, reports, full feed.                                                                                       | Reflects "every coach manages a list of players" + "admin distributes players".                                                                                                                                                                               |
| D-017 | **Profit margin = (collected − expenses) ÷ collected**, per month/year.                                                                                                                                                                                                                                                                                | Standard definition; shows "—" when collected = 0.                                                                                                                                                                                                            |
| D-018 | **Arabic default (RTL)**, English toggle; **Latin digits** in both; Gregorian dates.                                                                                                                                                                                                                                                                   | Bahrain convention; consistent with CPR/phone input.                                                                                                                                                                                                          |
| D-019 | **Activity log written server-side** (triggers/RPCs), never from the client; stores a snapshot summary.                                                                                                                                                                                                                                                | Tamper-proof audit; survives deletes.                                                                                                                                                                                                                         |
| D-020 | **Composite writes via Postgres RPCs** (create_subscription, save_attendance…), and the subscription total is recomputed server-side.                                                                                                                                                                                                                  | Atomicity + don't trust client totals. Formula exists in TS (preview) and SQL (authoritative).                                                                                                                                                                |
| D-021 | **No self-signup.** Admin creates coach accounts through a `create-coach` Edge Function (service role). The first admin is seeded.                                                                                                                                                                                                                     | Closed internal system.                                                                                                                                                                                                                                       |
| D-022 | **Theme derived from the logo** (blue `#1860C8`, pink `#E02068`, white shield, navy for depth) because no public brand guide exists. Fonts Cairo + Poppins.                                                                                                                                                                                            | Owner asked to "match their theme"; see [06-design-system.md](06-design-system.md).                                                                                                                                                                           |
| D-023 | **Attendance status = present / absent** only.                                                                                                                                                                                                                                                                                                         | Keep it simple and fast on mobile; extend (late/excused) later if asked.                                                                                                                                                                                      |
| D-024 | **Session roster = the session coach's active players**; players lacking an active subscription get a warning badge but can be marked.                                                                                                                                                                                                                 | Predictable and simple; no per-session enrollment.                                                                                                                                                                                                            |
| D-025 | **Tooling:** Vite 8 + React 19 + TS 6, Tailwind v4, Vitest 5, ESLint 10 (flat config), single `tsconfig.json`, npm.                                                                                                                                                                                                                                    | Latest stable at scaffold time (Sep 2026).                                                                                                                                                                                                                    |
| D-026 | **`Select` is a native `<select>`**, not Radix Select.                                                                                                                                                                                                                                                                                                 | Best phone UX (OS picker), RTL-safe, zero JS; Radix Select is heavier and awkward on mobile.                                                                                                                                                                  |
| D-027 | **Phone tab labels can differ from page titles** (`tabLabel`): English "Billing" for Subscriptions.                                                                                                                                                                                                                                                    | 13px labels must fit ~78px; Arabic label fits as-is.                                                                                                                                                                                                          |
| D-028 | **Typed i18n keys from the English JSON**, namespaces registered in `src/lib/i18n-resources.ts`; ar/en parity and the physical-direction-class guard are Vitest tests (`src/test/conventions.test.ts`) rather than an ESLint rule.                                                                                                                     | Catches missing keys at compile time; the guard runs with `npm test` so it can't be skipped.                                                                                                                                                                  |
| D-029 | **Shield is an SVG component; Radix is consumed through the unified `radix-ui` package**; `class-variance-authority` for component variants.                                                                                                                                                                                                           | One dependency, tree-shakeable; replaces the planned CSS clip-path shield (a clip-path can't draw the curved outline).                                                                                                                                        |
| D-030 | **The hosted Supabase project is the development backend** (no Docker needed). Migrations are applied to it with the Supabase MCP (`apply_migration`); the files in `supabase/migrations/` stay the source of truth. Local `npx supabase start` still works (`config.toml`, `seed.sql`).                                                               | The owner connected a hosted project. MCP records each migration under its _apply_ timestamp, so the hosted history names differ from the file timestamps; content is identical. If a CLI-driven flow is adopted later, run `supabase migration repair` once. |
| D-031 | **Database tests are pgTAP** files in `supabase/tests/database/`, each inside a transaction that is rolled back. Run with `npx supabase test db` (local) or through the MCP `execute_sql` against the hosted project. An in-process PGlite harness was tried and **removed** at the owner's request.                                                   | Tests the real Supabase (real `auth`, roles, grants), and never leaves data behind. 131 assertions cover isolation, guards, constraints, activity logging and a privilege audit.                                                                              |
| D-032 | **Later-phase RPCs are not stubbed in Phase 2.** Phase 2 ships `remove_player` only; `create_subscription`, `record_payment`, `save_attendance`, reports, … arrive with the phase (and tests) that use them.                                                                                                                                           | A stub that nothing calls and nothing tests is dead code; signatures in `04-data-model.md` remain the contract.                                                                                                                                               |
| D-033 | **Player removal is the `remove_player(id)` RPC** (SECURITY DEFINER, checks ownership), not a plain `UPDATE deleted_at`. Restoring is admin-only.                                                                                                                                                                                                      | Postgres re-checks the SELECT policy on the updated row, and removed players are deliberately invisible to coaches, so a plain UPDATE fails for them.                                                                                                         |
| D-034 | **A coach can read only their own profile** (the matrix said "self + names of all coaches").                                                                                                                                                                                                                                                           | Stricter and simpler: coaches never see other coaches' data. Display names come from `activity_log.summary` snapshots or RPC joins.                                                                                                                           |
| D-035 | **Helper is `current_user_role()`**, not `current_role()`.                                                                                                                                                                                                                                                                                             | `current_role` is a reserved SQL keyword.                                                                                                                                                                                                                     |
| D-036 | **Deny by default:** `anon`, `authenticated` and `PUBLIC` get no privileges on new tables/functions; each migration grants back exactly what is needed. The privilege-audit tests fail if this regresses. Supabase's advisor flags the helper functions as "executable by signed-in users" — intentional, RLS policies call them as the invoking role. | Defence in depth beyond RLS.                                                                                                                                                                                                                                  |
| D-037 | **Auth behaviour:** users whose profile is missing or inactive are signed out (at login and mid-session); the profile's `preferred_language` is applied once after sign-in and later language toggles are saved back; the TanStack Query cache is cleared on sign-out so data never leaks to the next user of the device.                              | Closed internal system on shared phones.                                                                                                                                                                                                                      |
| D-038 | **`coach.created` is logged by the Edge Function** with the service role, not by a trigger.                                                                                                                                                                                                                                                            | A trigger on `profiles` would see `auth.uid()` = null and lose the acting admin.                                                                                                                                                                              |
| D-039 | **`VITE_SUPABASE_ANON_KEY` holds the project's publishable key** (`sb_publishable_…`); the legacy anon JWT also works.                                                                                                                                                                                                                                 | Supabase's recommended key type; same public-by-design role.                                                                                                                                                                                                  |
| D-040 | **No subscription-status badge on the players list in Phase 3.** The column is added in Phase 4 when there is data behind it.                                                                                                                                                                                                                          | A "no subscription" badge on every row would be misleading; the phase file only asked for a placeholder.                                                                                                                                                      |
| D-041 | **Players list = server-side search (name / CPR / phone), coach and "has condition" filters, sort by name or newest, 20 per page with a "Show more" button.** Offset paging with `id` as tie-breaker; the search text is stripped of characters that mean something in a PostgREST `or(...)` filter.                                                   | An academy has hundreds of players, not millions; simple and predictable beats infinite scroll.                                                                                                                                                               |
| D-042 | **A player's coach changes only through the dedicated actions** — the single "Coach assignment" card on the detail page and bulk assign in the list (`assign_players`, admin only, target must be an active coach, unassign allowed, unchanged rows are skipped and not logged). The edit form never sends `coach_id`.                                 | One audited path; a coach can never reassign by editing.                                                                                                                                                                                                      |
| D-043 | **Duplicate CPR:** the form links to the existing player only if the caller may see it (RLS); otherwise it says the CPR is registered with another coach, without naming anyone.                                                                                                                                                                       | Blocks the duplicate without leaking another coach's players.                                                                                                                                                                                                 |
| D-044 | **No plural-suffixed i18n keys.** Arabic has six plural forms and the ar/en key-parity test compares raw keys, so counts are plain interpolation (`{{n}}`) in sentences that read correctly for any number.                                                                                                                                            | Keeps both languages in lock-step without per-language key sets.                                                                                                                                                                                              |
| D-045 | **Players pages are shared components** mounted under `/admin/players` and `/coach/players`; every link is built from `usePlayersBasePath()` so a coach never lands in the admin area.                                                                                                                                                                 | Matches the architecture doc; RLS scopes the data.                                                                                                                                                                                                            |
